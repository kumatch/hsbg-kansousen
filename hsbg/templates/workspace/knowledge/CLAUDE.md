# CLAUDE.md — 知識庫の規約

このフォルダ（`knowledge/`）を編集するときに守ること。構成と分析との約束は `README.md`。

## 境界（最重要）

- **ユーザー自身のプレイから得たものは入れない**。戦績、勝率、「このカードは強かった」、プレイ方針、推奨は書かない（それは `../analysis/` の分析が持つ）
- **評価を書かない**。公式ノートの区分（強化 / 弱体化 / 変更 / 追加 / 削除 / 復帰）は書いてよいが、「強い」やティアリストは書かない
- 事実には必ず**出典**を付ける。出典の無い記述は `要確認` と書く
- AI の学習知識だけを根拠にしない。特に現シーズンのカードや仕組みは学習の範囲外のことが多いので、パッチノート・カードデータ・ユーザーが示した情報を出典にする。
  一般ルール（`basics/`）を学習知識で書くときは出典を「一般知識（要確認）」とし、ユーザーの確認を経て外す

## 出典の優先順位

1. 公式パッチノート（hearthstone.blizzard.com のニュース）
2. ユーザーが貼ったパッチノート・ゲーム内の表示（出典欄に「ユーザー提供 YYYY-MM-DD」）
3. HDT のカードデータ `%APPDATA%\HearthstoneDeckTracker\CardDefs\CardDefs.base.xml` / `CardDefs.<言語>.xml`
   （ルート要素の `build` 属性がクライアントのビルド番号。HDT が取り直すまで更新されないので、パッチより古いことがある。照合の前にファイルの更新日時を確かめる）
4. それ以外の Web 情報（wiki など）は補助。使ったら URL と取得日を書く

カードデータとパッチノートが食い違ったらパッチノートを正とし、食い違いを記録する。

## 書き方

- カード名はクライアントの表記 + 英語名 + CardID を併記する（例: `日本語名 / English Name / BG36_108`）。分析の出力と表記を揃える
- 日時はユーザーのタイムゾーンで書き、タイムゾーンを明記する（例: JST）。適用日時はできるだけ分単位。分からなければ日付だけ書いて `要確認`
- 数値の変更は「変更前 → 変更後」。片方しか分からなければ `?`
- カード・仕組みの事実には「確認: <CardDefs の build> / <その時点で記録済みの最新パッチ>」を付ける（出典がパッチノートだけなら「確認: <パッチ>」）
- `season/current.md` は常に「今」を表す。パッチが来たら先に `patches/` に記録してから `current.md` を更新する
- ファイルを移動・改名しない（分析がパスで参照する）

## コミット

- コミットはユーザーの許可を得てから行う
- 推奨する単位とメッセージ（分析が `git log` で読む）: パッチ 1 つ = 1 コミット `patch: <version>`、既存の記述の誤りの修正は別コミット
  `fix: <何を直したか>`、それ以外は `season: ...` / `basics: ...` / `docs: ...`
